# アーキテクチャ

| 層 | 役割 |
| --- | --- |
| src/pages・src/components | 画面、フォーム、ナビゲーション |
| src/hooks | インターバルタイマー |
| src/services | ローテーション、入力検証、分析、バックアップ、AIアダプターの契約 |
| src/repositories | カタログの読み込み、セッションの永続化、参照制約付き削除 |
| src/db・src/types | Dexie スキーマ、初期データ、型 |
| src/utils・src/tests | 日付処理、回帰テスト |

記録とセットを単一トランザクションで保存する。UI は入力の更新を順番に永続化する。履歴の編集は保存操作で確定する。ローテーションは最新の完了セッションの日付と作成日時を基準に求める。

指定構成に Vite PWA プラグインを追加し、ビルド時に Workbox のプリキャッシュとマニフェストを生成する。ビルド成果物は静的配信できる。Vitest では fake-indexeddb を使い、Windows でも DB の統合テストを実行できる。

第2段階の計算は `growth.ts`、`readiness.ts`、`planning.ts` に集約した。端末内提案は全体準備3分、種目ごとの準備90秒、1セット45秒、同種目内のセット間休憩を見積もり、分単位で切り上げる。同日の運動予定がある場合は脚の提案を抑える。重量の増加は前回から14日以内で回数・セット数・RIRを満たした場合に限り、5%か2.5 kgの小さい方までとする。状態が悪い場合や前回強度が高い場合は重量を落とし、痛みがある日は重量付きの提案を保留する。

`coaching.ts` は対象期間のプロンプトを組み立てる。種目ごとの前回実績は共有期間の履歴への参照位置で示し、セットを重ねて送らない。直近7日集計も指定期間との共通範囲から計算する。画面上の外部リンクは通常のリンクで、プロンプトは利用者がコピーして貼り付ける。

`coachMenu.ts` はコードフェンス、形式、数値、種目ID・名称を検証し、利用ジム・時間・ローテーション・当日の状態と照合する。提案を登録する直前に `repositories/coach.ts` が同じ検証をトランザクション内で実行する。提案を開始する際にも、現在のローテーション、設備、当日のコンディションで再照合する。

第3段階ではPagesのベースパスをビルド時に指定し、画面をハッシュで切り替える。相対スコープのマニフェストとSWはサブディレクトリ内で完結する。Service Workerの待機を検知して手動更新を表示し、保留中の書き込みとIndexedDBの下書きを確認してから待機中のWorkerに切替を要求する。自分で更新を選んだ画面だけが切替完了時に再読み込みする。

配信ワークフローは手動実行とし、型チェック、テスト、ビルド、配布物の許可リスト検査が完了してから `dist/` を送る。バックアップ・個人設定はローカルの除外対象とする。
